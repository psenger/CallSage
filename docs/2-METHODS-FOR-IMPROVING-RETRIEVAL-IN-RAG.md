# Summary: Improving RAG Retrieval from 50% to 95% Recall

## The Problem

A client project building a chatbot for customer service staff was only retrieving correct documents 50-60% of the time using standard RAG approaches:

- **Vector search failed** - too fuzzy, returning semantically similar but incorrect results (e.g., other massage types instead of Swedish massage, other Finnish cities instead of Helsinki)

- **BM25 full-text search struggled** - BM25 (Best Match 25) is a ranking algorithm that scores documents based on keyword frequency, considering term frequency, inverse document frequency, and document length. The problem: it ranked documents by how many times search terms appeared, not by relevance. For example, searching "Swedish massage in Helsinki":
  - A location offering many massages (but NOT Swedish) might mention "massage" 6 times, plus serve "Swedish" meatballs = **7 matches** ✗
  - A location offering only Swedish massage in Helsinki = **3 matches** ✓
  - BM25 would incorrectly rank the first document higher despite being completely wrong
  
- **Language issues** - Finnish word conjugation caused missed matches

## The Solution

Two key changes using LLMs to improve retrieval:

**1. At Indexing Time:**

- Used an LLM to extract structured data (services list) from freeform descriptions
- Added a new "services" field to the search index

**2. At Query Time:**

- Used an LLM to convert natural language queries ("Swedish massage in Helsinki") into structured filters
- Applied precise filtering: `city = "Helsinki" AND services contains "Swedish massage"`

## The Results

- Recall improved to **95%+**
- Almost all user issues disappeared
- Trade-offs were minimal: slightly higher indexing costs and small latency increase (both easily justified by massive improvement)

## Key Takeaway

**"Retrieval-augmented generation works both ways"** - LLMs can be used not just for generation, but also to build better retrieval systems through intelligent query restructuring and data extraction.
